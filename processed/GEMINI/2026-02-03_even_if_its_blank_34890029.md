### GEMINI
Yes, if you just installed the new driver, that file should be empty or not exist at all. In Linux, "empty" just means the system is using all the standard defaults. By adding your line to it, you are creating a "manual override." Since you just switched to the Proprietary (Closed) drivers, we can finally force the system to listen. The Final "Kill the Flicker" Sequence Open the blank file: sudo nano /etc/modprobe.d/nvidia.conf Paste this exact line into the empty space: options nvidia NVreg_EnableGpuFirmware=0 Save and Exit: (Ctrl+O, Enter, Ctrl+X). Bake it into the Boot (CRITICAL): Because NVIDIA drivers load very early in the boot process, the system won't "see" your new file unless you rebuild the boot image. Run this command: sudo mkinitcpio -P Reboot your PC. How to verify you won Once you're back at the desktop, run this: nvidia-smi -q | grep "GSP Firmware" If it says N/A: You have won. The GSP firmware is disabled. Open OBS; the "strobe light" flickering should be gone forever. If it still shows a version number: The system is ignoring the file. This happens if your bootloader (like GRUB or Limine) is bypassing the standard config. The "Fallback" if it's still flickering If it still flickers after the reboot, it’s a Refresh Rate Mismatch between your two 165Hz monitors. Go to Settings > Displays. Turn OFF Variable Refresh Rate (VRR/G-Sync). Set both monitors to exactly 144Hz. Run the mkinitcpio -P command and reboot now. Does nvidia-smi finally show N/A for the GSP Firmware?
