### GEMINI
That "works in Desktop but crashes in Game Mode" loop is a classic Steam Deck symptom of a configuration mismatch or a pathing conflict between the two modes. When you run Citron in Desktop mode, it uses its own window manager and environment. When Steam launches it in Game Mode (via the shortcut SRM made), it forces the emulator into a "Gamescope" container. If the update changed how the game initializes (e.g., higher memory usage, different resolution, or requiring a specific "Docked" state), Game Mode will choke and kick you back to the home screen because it thinks the app has hung. Here is the objective, no-nonsense way to do this without breaking your setup again. 1. The Space "Lie" You are using a symbolic link to save space. However, when you "Install Files to NAND," Citron copies that update to your internal SSD (/home/deck/.local/share/citron/nand/...). The Trap: If your internal drive is near full, the update might "finish" but result in a corrupted or zero-byte file in the NAND. This causes an infinite loading screen in Game Mode because Gamescope is less tolerant of file errors than the Desktop environment. Fix: Ensure you have at least 3x the size of the update free on your internal SSD before you start. 2. The "Update Manager" vs. "Install to NAND" You mentioned using an "Update Manager." In Citron/Yuzu-based emulators, there is a distinction. The Correct Way: Always use File > Install Files to NAND. Why: This properly registers the Title ID in the metadata folder. If you just "pointed" the emulator to an update file elsewhere, Game Mode often fails to pass that secondary file path through the Steam shortcut. By installing to NAND, the update is "baked into" the emulator's internal logic, so the Steam shortcut only needs to point to the base ROM. 3. The "Game Mode" Crash Fix (The Real Culprit) If it works in Desktop but not Game Mode, the update likely toggled a setting that Gamescope hates. Before you launch in Game Mode: Open Citron in Desktop Mode. Right-click the game > Properties. Ensure the update is checked in the Add-ons tab. Go to System. Ensure "Language" and "Region" are explicitly set (not just "Auto"). Crucial: Go to Graphics. Change the "Graphics API" to Vulkan (if it isn't) and set "Window-Adapting Filter" to Bilinear or Nearest Neighbor. High-end filters like FSR can sometimes cause the Game Mode "infinite spin" on launch after an update. Clear Shaders: Right-click the game > Remove > Remove All Pipeline Caches. Updates often render old shaders incompatible; Desktop mode might struggle through it, but Game Mode will just kill the process. The Precise Execution Plan Verify Space: Check your internal SSD. Delete some junk if it's tight. Clean Slate: In Citron (Desktop), right-click the game > Properties > Add-ons. Uncheck any old updates. Proper Install: Go to File > Install Files to NAND. Select your update .nsp. Wait for the "Successfully Installed" prompt. The Test: Launch the game once in Desktop Mode. If it reaches the title screen, the update is good. Shader Purge: Right-click the game > Remove > Remove All Pipeline Caches. (This is the #1 reason for Game Mode crashes). Launch Game Mode: Switch back and try. The Opportunity Cost: If you keep trying to "link" everything and dodge the NAND installation, you are going to spend 4 hours troubleshooting a problem that a 5-minute NAND copy would have solved.
