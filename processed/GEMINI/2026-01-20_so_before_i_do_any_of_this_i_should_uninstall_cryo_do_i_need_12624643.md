### GEMINI
To answer your question directly: Yes, uninstall CryoUtilities, but NO, do not reset the UMA Buffer. Here is the strategic breakdown of why and exactly what to do next. 1. Why you should uninstall CryoUtilities (for now) You are on a newer version of SteamOS that uses ZRAM (which is why free -h showed 5.8GB). CryoUtilities was designed for the old SteamOS swap file system. When you ran it, it clearly failed to hook into the new system (giving you the "Unknown" error). The Conflict: Having a broken CryoUtilities installation can cause "zombie" settings that fight the native SteamOS memory management. The Action: Use the Uninstall CryoUtilities icon on your desktop. When it asks if you want to revert to stock settings, say YES. We want a clean slate so we know exactly what is happening with your RAM. 2. Why you must KEEP the 4G UMA Buffer The UMA Frame Buffer (4G) change in the BIOS is separate from CryoUtilities. The Truth: Tears of the Kingdom is a memory hog. By setting this to 4G, you are ensuring the GPU always has a floor of 4GB of VRAM. Without this, the system tries to dynamically shift memory between the CPU and GPU. For TotK, this "shifting" often happens too slowly in Game Mode, causing the exact "Launching... Crash" loop you are seeing. Leave it at 4G. It is the single most effective hardware-level tweak for Switch emulation on the Deck. The Precise Plan to Fix the "Update Crash" Since the update runs in Desktop but not Game Mode, and CryoUtilities is out of the picture, do this in order: Step 1: Fix the Citron "Full Screen" Bug Game Mode hates it when an emulator tries to "ask" for permission to go fullscreen. Open Citron in Desktop Mode. Go to Emulation > Configure > Graphics. Set Fullscreen Mode to "Exclusive Fullscreen" (NOT Borderless). Set Aspect Ratio to "Force 16:10". In Advanced Graphics, uncheck "Enable Compute Pipelines" (this is a known crasher for TotK updates on recent SteamOS versions). Step 2: The SRM "Refresh" You said you just set up Steam ROM Manager, but when you updated the game in the NAND, the Title ID or the way Citron "calls" the game might have changed internally. In Desktop Mode, open Steam ROM Manager. Click Settings (bottom left) > Remove all added app entries. Go back to your Citron parser and click Parse > Save to Steam. Check the Shortcut: In the Steam Library, right-click TotK > Properties. Ensure the Target points to the Citron AppImage and the Launch Options points to the Base ROM (the one in /home/internal_games). Step 3: The Manual Memory Kick Since we uninstalled CryoUtilities, let's give the Deck one manual instruction to help it handle the update's memory spike: Open Konsole. Type: sudo sysctl -w vm.swappiness=100 Enter your password. (This tells the Deck: "If you run out of RAM, use the SSD immediately instead of crashing.") Why this will work The update to 1.2.1 made the game heavier. In Desktop Mode, the Deck is "lazy" and lets the game take its time to load. In Game Mode, the Deck is a "security guard"—if the game takes too long to respond because it's struggling with memory or a bad fullscreen handshake, the guard kicks the game out (the crash back to Home). What to do now: Uninstall CryoUtilities, keep the BIOS at 4G, and try the Citron "Exclusive Fullscreen" setting. If it still crashes, tell me: Does the Steam logo spin for 10+ seconds before crashing, or does it happen instantly? (Instant = Path/Shortcut error. 10+ seconds = Memory/Handshake error).
