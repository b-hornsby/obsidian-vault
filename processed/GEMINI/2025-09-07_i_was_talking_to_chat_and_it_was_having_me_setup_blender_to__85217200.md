Setting up communication between your external CrewAI agents and Blender is the most crucial step. Since Blender runs on its own internal Python environment, you can't directly call its functions from your external virtual environment. The solution is to use Blender's command-line interface (CLI) as a bridge. Think of it this way: your CrewAI agent is the Director, and the Blender executable is the Actor. The Director doesn't act directly; instead, it gives the Actor a script to perform and the Actor then executes it. Here’s how to set this up: 1. The Blender Script (The Actor's Script) Create a Python file inside your scripts/ directory. This script will contain the actual Blender commands for things like creating a mesh, setting up a camera, or rendering. This is the script the Director will tell the Actor to perform. scripts/create_cube.py import bpy # This code will run inside Blender's environment bpy.ops.mesh.primitive_cube_add(location=(0, 0, 0)) # To save the .blend file bpy.ops.wm.save_as_mainfile(filepath="//my_scene.blend") 2. The Agent Script (The Director's Commands) Now, inside your agents/ directory, the director.py or animation.py agent will use Python's subprocess module to run Blender in the background and tell it which script to execute. This is the communication bridge. agents/animation.py import subprocess import os # Define the paths to your Blender executable and the script blender_executable = "blender" # Or the full path to your Blender executable script_path = os.path.join("..", "scripts", "create_cube.py") # This is the command to run Blender headless and execute the script command = [ blender_executable, "--background", "--python", script_path ] # Run the command try: subprocess.run(command, check=True) print("Blender script executed successfully.") except subprocess.CalledProcessError as e: print(f"Error running Blender script: {e}") How It All Works blender: This calls the Blender executable. Make sure it's in your system's PATH, or provide the full path to the executable. --background: This is a crucial flag. It tells Blender to run without the graphical user interface (GUI), which is also known as "headless mode." This is perfect for automation and saves significant system resources. --python <script_path>: This flag tells Blender to run the specified Python script. Blender's internal Python interpreter handles the script. Passing Data Between the Scripts Your agents will need to pass information, such as user prompts or specific parameters, to the Blender scripts. You can do this using command-line arguments. scripts/create_and_color_cube.py import bpy import sys # Get arguments passed from the external script # sys.argv will contain ["--", "red", "my_cube_name"] args = sys.argv[sys.argv.index("--") + 1:] color_name = args[0] object_name = args[1] # Set up the material with the specified color mat = bpy.data.materials.new(name=f"{color_name}_material") mat.diffuse_color = (1.0, 0.0, 0.0, 1.0) # Example: red color # Create a cube and link the material bpy.ops.mesh.primitive_cube_add(location=(0, 0, 0)) obj = bpy.context.active_object obj.data.materials.append(mat) obj.name = object_name bpy.ops.wm.save_as_mainfile(filepath=f"//my_scene_{object_name}.blend") The external agent would call this with the following command: command = [ blender_executable, "--background", "--python", script_path, "--", "red", "my_cube" ] The -- flag is important as it separates Blender's own arguments from the ones you want to pass to your script. This subprocess method is the industry standard for automating Blender and will form the backbone of your agent's functionality.
