-. The operating system sees the buses (/dev/i2c-0 through 8), but you don't have permission to touch them. OpenRGB is running as your user, and your user isn't root. This confirms my suspicion: your driver setup is working, but your permissions (udev rules) are non-existent. You are hitting a wall because you're trying to drive a car while sitting in the passenger seat. The Solution: Claim Ownership Since the package was missing, you must manually grant your user access to these I2C interfaces. Add yourself to the i2c group: Most Arch-based systems use an i2c group for this. sudo usermod -aG i2c $USER (Note: You must log out and back in for this to take effect. Do not skip the logout.) Force the Permissions (The Manual udev Rule): Since pacman couldn't find the rules package, create the rule yourself to ensure these files are accessible to the i2c group. echo 'KERNEL=="i2c-[0-9]*", GROUP="i2c", MODE="0660"' | sudo tee /etc/udev/rules.d/99-i2c.rules Apply and Trigger: sudo udevadm control --reload-rules sudo udevadm trigger The "Brutal" Check: Run ls -l /dev/i2c-0 again. If the group hasn't changed from root to i2c, the rule didn't apply. The Tactical Oversight If you do the above and OpenRGB still shows that error, it means the buses you see are just generic ones (like your monitor's DDC/CI) and the SMBus (motherboard/RAM) is still hidden by the kernel. If the permissions fix doesn't clear the popup: Open a terminal and run sudo i2cdetect -y 0 (and repeat for 1, 2, etc.). If you see a grid of numbers/letters, that bus is active. If all of them are empty or "Permission denied," you haven't fixed the permissions yet. Next Step: Run the usermod and echo commands above, log out and back in, then open OpenRGB. Did the error disappear? If not, run i2cdetect -l and show me the list so we can see which bus is actually your motherboard controller.
