In that screenshot, your Blue Microphones Analog Stereo is visible and unmuted, but the level meter is flat (black). If you are talking and that bar isn't jumping with a blue/gray highlight, the hardware is "open" but no data is flowing. This confirms the USB handshake failure. The kernel sees the device name, but the internal clock of the Yeti didn't sync, so it's sending zeros. The Final, Brutal Fix Since the "Electronic Replug" script worked earlier to make the device show up, you need to automate that "kick" to happen every time you log in. This replaces the need to physically touch the cable. 1. Create a "Yeti-Reset" Script Run this in your terminal to create a permanent fix script: printf '#!/bin/bash\nsleep 5\necho 0 | sudo tee /sys/bus/usb/devices/1-3/authorized\nsleep 1\necho 1 | sudo tee /sys/bus/usb/devices/1-3/authorized\nsleep 2\nsystemctl --user restart pipewire wireplumber' > ~/.yeti-reset.sh chmod +x ~/.yeti-reset.sh 2. Allow it to run without a password Because sudo requires a password, the script will fail at boot unless we tell the system this specific USB command is safe. Run sudo visudo Scroll to the very bottom and add this line (replace yourusername with your actual login name): yourusername ALL=(ALL) NOPASSWD: /usr/bin/tee /sys/bus/usb/devices/1-3/authorized Save and exit (Ctrl+O, Enter, Ctrl+X). 3. Add to Autostart Now, open your System Settings -> Autostart and add ~/.yeti-reset.sh as a login script. Why this is the only way: Your Yeti is failing to initialize because your motherboard's USB controller and CachyOS are moving too fast for the Yeti’s 15-year-old firmware. By toggling the authorized file 5 seconds after boot, you are performing a software-controlled replug. It forces the Yeti to restart its handshake when the system is actually ready to listen.
