That warning is essentially OpenRGB telling you it’s seeing double. You have two versions of the same permission file (udev rules), which can lead to conflicts where your hardware might not be recognized correctly or settings won't stick. In Linux, /usr/lib/udev/rules.d is usually for rules provided by the system/package manager, while /etc/udev/rules.d is for user-defined rules. The one in /etc generally takes priority, but having both is messy. How to Fix It The cleanest way to handle this is to remove the one in /lib (the system one) and keep the one in /etc, or vice versa depending on how you installed it. Most users find success deleting the duplicate in /usr/lib. Open your terminal and follow these steps: Remove the duplicate file: sudo rm /usr/lib/udev/rules.d/60-openrgb.rules (Note: If you'd rather be safe, you can move it to a backup folder instead of deleting it.) Reload the udev rules: Tell the system to refresh its memory so it stops looking for the file you just deleted. sudo udevadm control --reload-rules && sudo udevadm trigger Restart OpenRGB: Close the app completely and reopen it. The warning should be gone. Why did this happen? It usually happens if you manually installed OpenRGB (like via an AppImage or a script) and then later installed it through a package manager (like apt, pacman, or a PPA). Both methods tried to "help" by placing a rules file in their preferred directory.
