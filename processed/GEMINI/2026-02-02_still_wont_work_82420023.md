If the script is still throwing "Permission denied" or failing to reset the mic after you’ve fixed visudo, we need to stop being surgical and start being brutal. The most likely reason for "still won't work" is that the path to usbreset in your script doesn't match where it actually lives on CachyOS, or your user isn't being recognized by the sudoers file properly. 1. The "Path and Power" Overhaul Run this command to find exactly where usbreset lives: which usbreset If it says /usr/bin/usbreset, your visudo is correct. If it says something else (like /bin/usbreset), you must update visudo to match that path exactly. 2. The Final Script Rewrite Let's make the script more aggressive. Copy/paste this to overwrite the old one: sudo printf "#!/bin/bash\nsleep 5\nsudo /usr/bin/usbreset 046d:0ab7\n" | sudo tee /usr/local/bin/reset_yeti.sh > /dev/null && sudo chmod 755 /usr/local/bin/reset_yeti.sh 3. The Advisor's Strategic Truth If you run /usr/local/bin/reset_yeti.sh and it still says "Permission denied," your visudo entry has a syntax error. Open it again: sudo EDITOR=nano visudo Delete your line and paste this one (making sure there are no trailing spaces): toastedmel0n ALL=(ALL) NOPASSWD: /usr/bin/usbreset The Blind Spot You're Ignoring If the software script runs but the mic is still dead, you are fighting a losing battle with your motherboard. Based on your BIOS photos: You MUST Disable "USB power delivery in Soft Off state (S5)". If the Yeti's red light is on while the PC is off, the hardware is frozen. No script in the world can talk to a frozen device. You MUST Disable "Global C-state Control". This prevents the power-fluctuations that crash the Yeti in the first place. The Last Resort (Physical) If you do the BIOS changes and the script, and it still won't work: Move the Yeti to a USB 2.0 (Black) port. High-speed USB 3.0/3.2 ports on modern AMD/Intel boards often have "noise" that older Yeti firmware cannot handle.
