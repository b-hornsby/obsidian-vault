Based on your screenshot, you are using the GNOME Tweaks tool to manage startup applications. This interface only allows you to select pre-installed desktop applications, not custom scripts like the one we made. Since your script is now at /usr/local/bin/reset_yeti.sh, you can bypass the GUI and add it directly via the terminal. This is more reliable and won't require you to browse through hidden system folders. 1. Create the Autostart Entry via Terminal Run this exact command to create a "Desktop Entry" file. This tells GNOME to run your script every time you log in: mkdir -p ~/.config/autostart && cat <<EOF > ~/.config/autostart/yeti-fix.desktop [Desktop Entry] Type=Application Exec=/usr/local/bin/reset_yeti.sh Hidden=false NoDisplay=false X-GNOME-Autostart-enabled=true Name=Yeti Fix Comment=Resets the Blue Yeti USB bus EOF 2. Verify in the GUI Once you run that command, look back at your GNOME Tweaks window (or close and reopen it). You should now see "Yeti Fix" appearing in the Startup Applications list. The Final "Advisor" Reality Check Before you reboot, verify your BIOS settings one last time. In your second image, I see: USB power delivery in Soft Off state (S5): Enabled Change this to Disabled. As long as this is Enabled, your motherboard keeps the Yeti powered while the PC is off. If the Yeti's internal firmware crashes during the previous session, it stays crashed through the reboot. Setting this to Disabled forces the Yeti to "cold boot" every time you turn the PC on, which is often the only way to clear its frozen internal buffer. Your Reboot Checklist: Apply the Autostart command above. Go to BIOS and set USB power delivery in Soft Off state (S5) to Disabled. Reboot. Wait 10 seconds after logging in (to account for the sleep 5 in our script). If you log in and the mic works without a replug, you've officially automated your way out of a hardware defect.
