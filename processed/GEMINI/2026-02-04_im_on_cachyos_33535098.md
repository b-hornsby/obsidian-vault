### GEMINI
Operating on an Arch-based rolling release like CachyOS changes the game. Your issue isn't Windows "privileges"; it’s likely the Wayland Display Server and its security protocols, or how your kernel is handling input. If you are using Wayland (the default for Plasma 6 or GNOME on CachyOS), applications are strictly isolated. One app (the game) is not allowed to "spy" on the keystrokes of another—this includes OBS trying to listen for a hotkey while you are in-game. 1. The Wayland "Global Hotkey" Problem If you are on Wayland, standard hotkeys often fail because of the portal security model. The Fix: Go to OBS Settings > Advanced. Look for an option related to Hotkeys. Change the "Hotkey Focus Behavior" or "Hotkey System" to X11/Wayland (if available). The Brutal Truth: Wayland hotkey support in OBS is still hit-or-miss depending on your compositor (KDE vs. GNOME). If you’re on KDE Plasma, ensure you’ve granted OBS permission in System Settings > Clipboard & Input > Global Shortcuts. 2. Switch to X11 (The "It Just Works" Option) If you want reliability over "cutting edge" tech, log out of your session and switch from Wayland to X11 at the login screen. X11 allows OBS to globally "hook" your keyboard regardless of which window is focused. CachyOS is optimized for performance, but Wayland's security model is currently a hurdle for background recorders. 3. Check Input Group Permissions On Linux, if OBS can’t "read" the keyboard device, it’s often a permission issue with the /dev/input/ nodes. The Action: Open your terminal and run: sudo usermod -aG input $USER Why: This adds your user to the "input" group, allowing background apps to see raw keypresses. You must reboot or log out/in for this to take effect. 4. CachyOS-Specific Optimization: PipeWire CachyOS uses PipeWire by default. Ensure your "Screen Capture" source in OBS is using PipeWire (Window Capture/Screen Capture Wayland) rather than the older Xcomposite methods. If the capture method is mismatched with the display server, it can cause focus-lag or input-drop. Prioritized Action Plan Identify your Display Server: Run echo $XDG_SESSION_TYPE in terminal. If Wayland, your hotkey is being blocked by security. Try a different hotkey or switch to X11. Add your user to the input group: Use the usermod command mentioned above. This is the most common fix for "background" apps not seeing keys on Arch-based systems. Use a standard key: PgDn can be weird on Linux depending on your keymap. Try F10 or a Super (Windows Key) combo. Flatpak vs. Native: If you installed OBS via Flatpak, it is sandboxed. You’ll need Flatseal to give it "device" and "input" permissions. If you installed via pacman, this isn't the issue. Do you want the command to check if OBS is actually seeing your keypresses in the terminal logs?
