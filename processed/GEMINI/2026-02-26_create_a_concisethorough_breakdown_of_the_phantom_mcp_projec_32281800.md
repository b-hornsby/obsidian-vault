### GEMINI
To provide Claude with a high-fidelity breakdown for a code review, we need to distinguish between the two existing components of the "Phantom MCP" project: the Docs Server (for knowledge) and the Wallet Server (for execution). Since you are looking to "get started building," I have framed this as a technical specification for the Phantom Wallet MCP Server—the engine that allows an AI to actually move assets and sign transactions. Project Specification: Phantom MCP Wallet Server Goal: A Model Context Protocol (MCP) server that provides a secure bridge between an LLM (Claude) and the Phantom Wallet ecosystem, enabling natural language execution of multi-chain transactions. 1. Architectural Overview Host: Claude Desktop / Cursor / Custom IDE. Client: MCP Client (TypeScript/Python SDK). Server: Node.js/TypeScript server implementing the MCP specification. Transport: Standard Input/Output (stdio) for local use or SSE for remote. Authentication: OAuth via Phantom Connect (PKCE flow) and session persistence via local encrypted JSON (~/.phantom-mcp/session.json). 2. Core Functional Requirements (The "Tools") Your implementation should expose the following tools to the LLM: Tool NameParametersPurposeget_wallet_addressesderivationIndex (optional)Retrieves public keys for Solana, Ethereum, Bitcoin, and Sui.sign_transactiontransaction (base64/hex), networkIdPrompts Phantom for a signature on a pre-built transaction.sign_messagemessage (string), networkIdUsed for dApp authentication/ownership proof.transfer_assetsto, amount, tokenMint, chainHigh-level abstraction for simple transfers.get_token_balancesaddress, networkIdProvides the agent with the "fuel" status of the wallet. 3. Technical Implementation Details Multi-Chain Support: Must handle Address Formats and Network IDs for: Solana: Mainnet-beta, Devnet. Ethereum: Mainnet (EIP-155:1), Sepolia. Bitcoin: Mainnet (Taproot/Native SegWit). Security Layer: PKCE Flow: Essential for secure OAuth without exposing secrets. Permission Scoping: The server must strictly limit what the AI can do without a manual "Approve" click in the Phantom UI. Transaction Simulation: (Recommended) Tool to simulate transactions before signing to show the LLM the expected balance change. 4. Code Review Focus Areas for Claude When you hand this to Claude, ask it to look specifically at: Schema Definitions: Are the JSON schemas for the tool arguments robust enough to prevent "hallucinated" parameters? Error Handling: How does the server report a "User Rejected" error from the wallet back to the LLM? Dependency Management: Ensuring @phantom/mcp-server or the underlying @solana/web3.js and ethers libs don't conflict. State Management: Handling the transition between "Logged Out" and "Session Active" gracefully. Strategy & Blind Spot Check The Opportunity Cost: If you spend all your time building the connection layer, you're missing the agentic layer. The real value is in the "System Prompt" that tells the AI when and why to use these tools (e.g., "If I ask to buy $SOL, check my USDC balance first"). The Risk: Most developers underestimate the friction of the OAuth callback. Ensure your local server can handle the redirect from the browser back to the CLI/IDE.
