### GEMINI
Okay, I understand you're looking for the exact rules to add when you click the "Add Rules" tab in Continue.dev's UI. Given that you want a Cursor-like experience, the "Rules" you need to add are not just singular, simple rules but rather a collection of best practices and guiding principles for the AI. To add these rules, you will be creating Markdown files (.md) inside the .continue/rules/ folder within your project's root directory. Continue.dev automatically picks up these files. Here are the concrete rules, split into separate Markdown files for better organization, that you should create: 1. General Coding Standards Rule File Name: 01-general-coding-standards.md Location: YOUR_PROJECT_ROOT/.continue/rules/ --- name: General Coding Standards --- # General Coding Standards for AI Assistant This rule provides common coding practices for the AI to follow. **Instructions for the AI:** 1. **Readability:** Prioritize clear, readable code over overly clever or concise solutions. 2. **Comments & Docstrings:** Always include comprehensive comments and docstrings (e.g., JSDoc, Python docstrings) for all functions, methods, classes, and complex code blocks. Explain their purpose, parameters, return values, and any non-obvious logic. 3. **Naming:** Use descriptive and self-explanatory names for variables, functions, and classes. Avoid single-letter names unless contextually obvious (e.g., loop counters `i`, `j`). 4. **Modularity:** Break down large functions or methods into smaller, more focused units, each responsible for a single task. 5. **Consistency:** Adhere to the existing code style, formatting, and conventions of the surrounding codebase. If a specific style guide is used (e.g., PEP8 for Python, ESLint for JavaScript), follow it strictly. 6. **Simplicity:** Prefer simpler algorithms and data structures unless the problem explicitly requires complexity for performance. 7. **Immutability:** Favor immutable data structures and pure functions where appropriate to reduce side effects and improve predictability. 8. **Type Safety:** If the language supports it (e.g., TypeScript, Python with type hints), always use explicit type annotations for parameters, return values, and variables. 2. Error Handling Rule File Name: 02-error-handling.md Location: YOUR_PROJECT_ROOT/.continue/rules/ --- name: Robust Error Handling --- # Robust Error Handling Guidelines This rule instructs the AI on best practices for error management. **Instructions for the AI:** 1. **Specific Exceptions:** Always use specific exception types (e.g., `ValueError`, `FileNotFoundError`, `TypeError`) instead of generic `except:` blocks or catching broad exceptions. 2. **Logging:** Implement comprehensive error logging. Log the full traceback, relevant variable states, timestamps, and contextual information to aid debugging. 3. **User-Friendly Messages:** If an error might be exposed to an end-user, ensure the message is clear, concise, and helpful, avoiding technical jargon. 4. **Graceful Degradation:** Design code to degrade gracefully in the face of errors, preventing complete application crashes where possible. 5. **Retry Mechanisms:** Consider and suggest appropriate retry mechanisms (e.g., with exponential backoff) for operations that might fail transiently (e.g., network requests, database connections). 3. Unit Testing Rule File Name: 03-unit-testing.md Location: YOUR_PROJECT_ROOT/.continue/rules/ --- name: Unit Testing Best Practices --- # Unit Testing Best Practices This rule guides the AI in generating and suggesting unit tests. **Instructions for the AI:** 1. **Test Coverage:** Aim for high unit test coverage, especially for new or modified functionality. 2. **Test Cases:** Include test cases for: * **Happy Path:** Typical, expected usage. * **Edge Cases:** Boundary conditions (e.g., empty inputs, maximum/minimum values, zero). * **Error Conditions:** How the code behaves when invalid input is provided or exceptions are raised. 3. **Test Independence:** Each test should be independent and not rely on the state of other tests. 4. **Descriptive Names:** Use clear and descriptive names for test functions/methods that indicate what they are testing (e.g., `test_add_two_numbers_positive`, `test_divide_by_zero_raises_error`). 5. **Mocks & Stubs:** Use mocks, stubs, or fakes for external dependencies (e.g., database calls, API requests, file system interactions) to ensure true unit isolation. 6. **Assertions:** Use appropriate and clear assertion methods (e.g., `assertEqual`, `assertTrue`, `assertRaises`). 4. Language-Specific Rules (Example for Python) File Name: 04-python-specific.md Location: YOUR_PROJECT_ROOT/.continue/rules/ --- name: Python Specific Rules --- # Python Specific Coding Rules This rule provides Python-specific guidance for the AI. **Instructions for the AI:** 1. **PEP8 Compliance:** Always adhere to PEP8 style guide for Python code formatting. 2. **List Comprehensions:** Prefer list, dict, and set comprehensions for creating collections where appropriate. 3. **Context Managers:** Use `with` statements for file operations and other resources that need proper cleanup. 4. **F-Strings:** Prefer f-strings for string formatting over `%` or `.format()`. 5. **Type Hinting:** Strictly apply type hints for function arguments and return values. 6. **Virtual Environments:** Assume development within a virtual environment. 5. Update your ~/.continue/config.yaml to reference these rules. Ensure your customRules section in config.yaml looks like this. The filepath parameter links to the .md files you just created. # ... (rest of your config.yaml content) ... customRules: - name: General Coding Standards filepath: .continue/rules/01-general-coding-standards.md alwaysApply: true # Apply these rules consistently across all requests description: "Core coding guidelines for readability, comments, and structure." - name: Robust Error Handling filepath: .continue/rules/02-error-handling.md alwaysApply: true description: "Guidelines for implementing robust and specific error handling." - name: Unit Testing Best Practices filepath: .continue/rules/03-unit-testing.md alwaysApply: true description: "Instructions for comprehensive and well-structured unit tests." - name: Python Specific Rules filepath: .continue/rules/04-python-specific.md alwaysApply: true globs: "**/*.py" # Apply this rule only to Python files description: "Specific style and best practices for Python development." # You would add similar blocks for JavaScript/TypeScript, etc., if needed: # - name: JavaScript/TypeScript Specific Rules # filepath: .continue/rules/05-js-ts-specific.md # alwaysApply: true # globs: "**/*.{js,jsx,ts,tsx}" # description: "Specific style and best practices for JS/TS development." Final Steps After Adding Rules: Save all files. Restart VS Code to ensure Continue.dev reloads the new rules. Test: When you ask the AI for code generation, modifications, or reviews, it should now more consistently follow the guidelines you've provided in these rule files.
