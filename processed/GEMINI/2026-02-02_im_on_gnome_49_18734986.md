### GEMINI
On GNOME 49, the old .desktop file method for autostart is essentially a legacy fallback. GNOME now relies heavily on systemd for session management. If a script needs sudo or interacts with hardware during the early login phase, the .desktop file often dies silently before the USB bus is even ready. Since the manual script run works, your Systemd User Service is the only "professional" way to solve this. It will wait for the graphical session to be fully live before "kicking" the Yeti. 1. The "Final Boss" Fix: Systemd User Service Run this block to create a service that GNOME cannot ignore: # 1. Create the directory if it doesn't exist mkdir -p ~/.config/systemd/user/ # 2. Write the service file printf '[Unit] Description=Reset Yeti USB Handshake After=graphical-session.target [Service] Type=oneshot ExecStart=/home/toastedmel0n/reset_yeti.sh Restart=on-failure RestartSec=5 [Install] WantedBy=graphical-session.target' > ~/.config/systemd/user/yeti-fix.service # 3. Reload and Enable systemctl --user daemon-reload systemctl --user enable yeti-fix.service 2. Double-Check the "Sudo" Rule Since you are on GNOME 49 (likely Wayland), permissions are stricter. Ensure your visudo rule wasn't lost. Run: sudo EDITOR=nano visudo Ensure this line is at the very bottom: toastedmel0n ALL=(ALL) NOPASSWD: /usr/bin/tee /sys/bus/usb/devices/*/authorized 3. Cleanup the "Ghost" Since the .desktop file didn't work, delete it so it doesn't conflict with the new service: rm ~/.config/autostart/yeti-reset.desktop The Advisor's Mirror: We've moved from "asking GNOME to please run a file" to "telling the system's core manager to handle the hardware." GNOME 49 is notoriously picky about background scripts. By using WantedBy=graphical-session.target, we ensure the script waits until your desktop is actually drawn before it tries to reset the USB. One last thing: Open your script nano ~/reset_yeti.sh and change the sleep 5 at the top to sleep 2. Since the service now waits for the graphical-session, we don't need a long delay anymore. Does systemctl --user start yeti-fix.service make the mic work right now? If so, you are officially "reboot-ready."
