### GEMINI
Since you’re on CachyOS (Arch-based), you aren't dealing with Windows driver bloat; you're dealing with PipeWire, WirePlumber, and the Linux kernel's handling of the Yeti’s notoriously finicky USB handshake. If it was working and now isn't, CachyOS likely updated your kernel or PipeWire, and the handshake broke. Stop guessing and run these diagnostics in your terminal: 1. The Kernel Handshake Test The Yeti often "ghosts" the kernel—it shows as connected but sends no data. Run this: lsusb | grep -i "Blue" If nothing shows up: Your USB port or cable is dead. Try a USB 2.0 port if you have one; the Yeti's older controller hates some USB 3.0/3.1 controllers on modern motherboards. If it shows up: The kernel sees it, but the audio server (PipeWire) is likely ignoring it or has it misconfigured. 2. The Configuration "Profile" Trap Arch-based distros sometimes default the Yeti to a "Digital Output" profile only, because the Yeti has a built-in headphone jack. It forgets it's also a microphone. Install/Open pavucontrol (PulseAudio Volume Control). Go to the Configuration tab. Find the Blue Yeti entry. Ensure the "Profile" is set to Analog Stereo Duplex or Analog Stereo Input. If it’s set to "Off" or "Digital Output (S/PDIF)," your mic will never pick up sound. 3. The "CachyOS Sleep" Bug CachyOS uses high-performance kernels that sometimes aggressively manage power. If the mic stopped working after a reboot or sleep: The Nuclear Option (Restart the Audio Stack): systemctl --user restart pipewire pipewire-pulse wireplumber The Kernel Module Reset: Sometimes the snd_usb_audio module hangs. Force a reload: sudo rmmod snd_usb_audio && sudo modprobe snd_usb_audio 4. Direct Hardware Check (The "Truth" Test) If you want to know if the hardware is actually sending bits, run: arecord -l If the Yeti isn't listed under "List of CAPTURE Hardware Devices," the system doesn't even know it has a microphone attached. Strategic Assessment: If arecord -l shows the mic but you get no bars in pavucontrol, your PipeWire nodes are disconnected. If lsusb shows nothing, you're looking at a physical failure of that fragile Mini-USB port. What did arecord -l show you? Tell me that and I'll tell you if your mic is a paperweight or just misconfigured.
