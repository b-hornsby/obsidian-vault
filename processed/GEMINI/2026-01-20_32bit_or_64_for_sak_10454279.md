# 32bit or 64 for sak?

### USER
32bit or 64 for sak?

### GEMINI
Go with the 64-bit version. The Steam Deck uses a 64-bit processor (AMD Van Gogh) and a 64-bit operating system (SteamOS/Arch Linux). Running the 64-bit version of SAK through Proton will allow it to utilize the Deck's memory and architecture more efficiently, which is critical when you're asking it to merge massive files like a 16GB Tears of the Kingdom base game and a 1.4.1 update. Pro-Tips for SAK on Steam Deck The "bin" Folder: Once you extract SAK, you'll see a bin folder. Copy your prod.keys into this folder. SAK uses a tool called hactool.exe internally to merge files, and it will fail immediately if the keys aren't sitting right next to it. Rename Keys: If SAK doesn't see your keys, rename the copy in the bin folder to keys.dat. Proton Version: Use Proton Experimental or Proton 9.0. If the SAK window looks weirdly small or text is cut off, go to the game's Properties > Launch Options in Steam and add: STEAM_FORCE_DESKTOP_UI_MODE=1 %command% Storage Space: Since you are merging a ~16GB XCI with an update, the process will create a new file. Ensure you have at least 20GB of free space on your SSD (which you already confirmed you do) because SAK doesn't overwrite; it creates a new "patched" version. The Advisor's Warning After you merge the file, your old shortcut in Steam ROM Manager will still point to the old .xci. Move the old base .xci and the .nsp update to a "Backup" folder so they don't get mixed up. Move your new, patched .xci into your /home/internal_games folder. Run Steam ROM Manager again. Once you have a single, merged 1.4.1 XCI, the "Handshake" error that was killing your Game Mode launch will be gone because the emulator won't have to look for external update files—it's all one piece of data.
