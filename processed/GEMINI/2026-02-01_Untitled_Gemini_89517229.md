This error is the classic "AppImage limitation" in action. Because AppImages are self-contained, they don't have the permissions to talk to your hardware (like your RAM or GPU) or install the necessary system-level "udev rules" that tell Linux it's okay for a normal user to control lights. Here is how to fix this properly on CachyOS. 1. The "Correct" Solution (Native Package) Since you are on CachyOS, you should stop using the AppImage. The native package in the Arch repositories handles all these permissions and drivers for you automatically. Uninstall/Delete the AppImage file. Install the native version: sudo pacman -S openrgb This package includes the necessary udev rules that the AppImage is complaining about. 2. Fixing the "Internal Devices" (I2C/SMBus) Your second screenshot shows that OpenRGB can't see your motherboard or RAM because the i2c-dev module isn't loaded. Load the module immediately: sudo modprobe i2c-dev Make it permanent: To ensure this works every time you reboot, run this command to create a config file: echo "i2c-dev" | sudo tee /etc/modules-load.d/openrgb.conf Identify your Chipset: AMD Users: You likely need i2c-piix4. Intel Users: You likely need i2c-i801. Try loading the relevant one (e.g., sudo modprobe i2c-piix4). 3. If you insist on keeping the AppImage If you really want to stick with the AppImage, you have to manually install the permissions it's missing: Install just the rules: sudo pacman -S openrgb-udev-rules Reload the system's hardware manager: sudo udevadm control --reload-rules && sudo udevadm trigger Summary: The AppImage is currently a "guest" that doesn't have the keys to your house. Installing openrgb via pacman makes it a "resident" with full access to your hardware.
