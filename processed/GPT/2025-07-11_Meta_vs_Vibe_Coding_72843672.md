### 🧠 **Meta Coding (Think like the Architect)**

**Definition (in your context):**  
Meta coding is about **thinking about the code before or while you're writing it** — planning, structuring, and designing the system. It’s high-level reasoning **about what the code should do**, **how parts should connect**, and **why you’re building it a certain way**.

**In Cursor and your project**, meta coding looks like:
- Designing the system architecture (e.g., “I need agents that escalate based on ticket type”)
- Thinking about the roles/tools each agent needs
- Mapping out workflows like: `User input → Categorizer agent → Dispatcher agent → Technician agent`
- Writing JSONs, configs, or profiles to define context, behaviors, or goals
- Debugging *structure* and *flow*, not syntax

**When you’re meta coding**, you’re essentially the **director or system designer**, guiding how things should be — sometimes writing “code about code.”

### 🧠💡 Best Practice: Combine Both

Here’s a good **flow** for someone like you:

1. **Meta code first.** Even just a simple sketch:
   - “I want an agent to detect the type of crypto ticket, another to choose the right tool, and another to post a meme.”
   - Write this down in `README.md` or a `project_plan.md`.
2. **Vibe code second.** Jump into Cursor:
   - Ask it: “Build a categorizer agent that can tell if a crypto question is about wallets, gas fees, or memes.”
3. **Review in meta mode again.**
   - Did this agent fit the architecture?
   - Should this be split into two tools?
   - Is this scalable or a one-off?
