### Honest Architectural Discussion

### Operator Model Architecture
- **Skill = Pilot:** Defines strategy, logic, risk limits, and decision trees. Lives in `~/.hermes/skills/solana-meteora-lp/SKILL.md`.
- **Agent = Operator:** Uses Hermes tools (Browser, Terminal, MCP, Memory) to execute trades and actions.
- **Repo = Reference Library:** Contains heavy math and complex transactions. Used as a black-box reference, not a runtime.
- **Memory = Experience:** Tracks what works (successful trims, bad luck, pool performance) so the agent gets smarter over time.
- **Key Insight:** A repo is a one-off; a skill is a living strategy that adapts to market conditions. The agent learns as it uses the skill.

### Key Decisions
- **Operator vs Repo:** The repo is treated as a reference library for heavy math/complex transactions; the Skill is the Pilot defining strategy, logic, and risk limits; Hermes (via the user) acts as the Operator executing via tools.
- **Learning Loop:** The skill now includes explicit instructions for the agent to log results, track metrics (trims, exits, IL), and adapt the strategy based on memory.
- **Toolchain:** Defined specific Hermes tools (Browser, Terminal, Memory) for market data, analysis, and execution.
- **Philosophy Shift:** The agent logic in the repo is the valuable part, but the skill format makes it repeatable and allows Hermes to learn over time.

## Lessons Learned
1. **Repo vs Skill:** A repo is a one-off runtime; a skill is a living, learning strategy. For Hermes-native execution, the skill approach wins despite lower reliability.
2. **Vault Path:** Obsidian vault lives at `C:\Users\<username>\Obsidian\<vault>\`, NOT in WSL home directory. Always double-check the path before writing.
3. **Operator Model:** The hybrid approach (Skill = Pilot, Repo = Reference, Agent = Operator) gives the best of both worlds: strategy clarity + execution flexibility + learning capability.
4. **User Preference:** User wants Hermes to be the "brains" behind everything — not just documentation, but active decision-making and execution.
